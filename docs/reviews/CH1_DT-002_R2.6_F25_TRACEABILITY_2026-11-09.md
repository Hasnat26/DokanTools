## 3. Additional focused issues

### CH1-26-01 — HIGH — Lifecycle event cardinality/linkage
R2.6 §3.3 lists request/submission audit and approval/post/audit events, but it does not fully specify whether approval and posting are distinct immutable events in each branch and how the audit event references each. Pending→rejected needs a clear reviewer authorization event. Define transition-specific event types and exact event counts.

### CH1-26-02 — HIGH — Confirmation identity and legacy actor provenance
Submission confirmation is described as authenticated submitter, but ledger payer confirmation does not have a complete persisted confirmer identity/evidence contract. Legacy actor KNOWN/UNKNOWN must be directly specified in each import branch. Do not use untrusted source actor as authenticated `created_by_user_id`.

### CH1-26-03 — HIGH — Reciprocal pair and concurrent absent-key arbitration
Operation row locking cannot itself serialize a key for which no operation row exists yet. Define exact unique-key arbitration, competing insert behavior, retry/re-read and deferred trigger lock order. If physical schema cannot support the selected exact mechanism, implementation remains blocked.

### CH1-26-04 — HIGH — Deadlock vs lock timeout
PostgreSQL `40P01` (deadlock) and `55P03` (lock timeout) are separate outcomes. A deterministic test must not accept either without splitting the test into separate scenarios.

### CH1-26-05 — HIGH — Non-deterministic test outcomes
T31/T32/T34/T41 require single outcomes and pinned fixtures. T34 should become T34A/T34B with separate B0/B1 snapshots. Any PO-pending write has pre-approval expected result: feature disabled/no-write.

### CH1-26-06 — MEDIUM — Supplemental tests
Replace generic “reject”, “ignore”, “unless verified” and alternative outcomes with exact fixture role, action, expected result and queryable evidence.

### CH1-26-07 — MEDIUM — DBA physical closure criterion
F25-07 remains pending. The DBA mapping must prove actual-schema reciprocal pair, trigger row-key behavior, FK cycles/deferrability and lock inventory. Any incompatibility returns to CH-1/CH-4; no silent alternative mechanism.
